无界鼠标独立版 0.102.2933.5 · 声音与麦克风共享（实验版）

支持什么
系统声音和麦克风各有“发送”和“接收”开关。可分别选择电脑、设备和 0–100% 音量。
设置会记住，程序下次启动后按配置恢复；网络或音频设备恢复后会自动重试。
默认四项全部关闭。只有启用发送、鼠标连接已认证、对方启用对应接收并通过音频认证后，
才会打开本机的相应采集设备。关闭共享会停止采集；程序不保存录音文件。

重要区别
系统声音共享：把所选播放设备正在播放的声音，送到另一台的耳机/音箱。
麦克风共享：把本机所选麦克风送到对端所选“播放设备”。若对端应用需要把它当麦克风，
对端须有虚拟音频设备，把播放端的声音转到录音端。仅选择音箱/耳机属于监听，不会让
会议软件凭空出现一个新的麦克风设备。
例如 VB-CABLE：本程序接收麦克风时选择 CABLE Input（播放端）；会议/游戏软件的
麦克风选择 CABLE Output（录音端）。两者名称容易混淆，请按播放/录音端区分。
虚拟设备需你自行安装并遵守其许可；本包不附带、不自动安装音频驱动。
官方说明及下载：https://vb-audio.com/Cable/

示例：耳机和麦克风插在 A，听 A/B 两台声音，B 也能使用 A 的麦克风
1. 两台退出旧版并解压完整新版，先完成鼠标配对。连接记忆与剪贴板功能保持可用。
2. 在 B 安装虚拟音频设备，并按其安装要求重新启动电脑。A 不需要虚拟音频设备。
3. 两台右键托盘图标，打开“声音与麦克风共享…”。设置页也有入口。
4. A 的“系统声音”页：
   - 发送：关闭。
   - 接收：开启，电脑选 B，设备选 A 的耳机，音量按需设置。
5. A 的“麦克风”页：
   - 发送：开启，电脑选 B，设备选 A 的物理麦克风，音量先用 100%。
   - 接收：关闭。
6. B 的“系统声音”页：
   - 发送：开启，电脑选 A，设备选 B 上应用实际正在播放声音的设备。
   - 接收：关闭。
7. B 的“麦克风”页：
   - 发送：关闭。
   - 接收：开启，电脑选 A，设备选 CABLE Input 或同类虚拟设备的播放端。
8. 两台端口均保留 15102，点击“保存并应用”。在 B 的会议/游戏软件中，将麦克风
   改为 CABLE Output。B 的应用扬声器仍用第 6 步选择的系统播放设备。
9. 检查窗口下方状态；两项对应通道应显示“正在发送”/“正在接收”。分别测试音乐、
   说话、静音和程序重启。不要仅凭“正在连接”判断声音已送达应用。

其他配置
- 可交换 A/B 角色。每种发送流一次选择一台电脑，每种接收流一次接受一个选定来源。
- 可以同时发送系统声音和麦克风，也可同时接收两种声音，使用独立设备和音量。
- 麦克风接收要求明确选择设备，避免无意播放到 Windows 默认音箱。
- “跟随 Windows 默认设备”会在默认设备改变后重建音频连接；指定的设备不可用时，
  会等待它恢复，不会悄悄改用其他麦克风。插拔设备后也可点击“刷新设备”重新选择。
- 两个方向同时发送系统声音时，接收输出必须与本机系统声音采集设备不同；同一个
  播放设备会被拒绝，以免声音循环放大。物理扬声器的声音仍可能被麦克风再次采集，
  建议使用耳机。本版不提供回声消除、降噪或远端虚拟设备驱动。
- “停止全部音频共享”立即停止当前音频，并保存四个开关为关闭。鼠标/剪贴板继续工作。
  正常关闭配置窗口不会停止已启用的共享。
- 发送系统声音不会自动静音源电脑，也不会更改 Windows 默认音频设备。

网络、延迟和配置
- 音频使用单独的 TCP 端口，默认 15102；两台必须设置相同端口，并允许可信局域网
  访问该端口。鼠标和剪贴板仍使用各自端口，不要将音频端口设为它们的端口。
- 声音连接使用 TLS 加密和双向配对码验证，复用已有的配对关系；配对码不会存入
  audio.json。鼠标连接断开或配对码改变时，音频通道会关闭并等待重新连接。
- 采用 48 kHz 浮点 PCM：系统声音立体声约 3.1 Mbit/s，麦克风单声道约 1.5 Mbit/s，
  不含网络/TLS 开销。没有采用有损压缩；面向可靠局域网。
- 接收缓冲上限默认 160 毫秒，可调 60–500 毫秒。它不是端到端延迟承诺；声卡、网络、
  队列和播放器都会增加延迟。拥塞时丢弃积压音频以追赶实时位置，可能出现短暂断音。
- 配置：%LOCALAPPDATA%\MouseWithoutBordersStandalone\audio.json；前一份为 audio.json.bak。
  损坏配置会停用音频并显示错误，不会覆盖原文件。可退出后保留原文件并恢复备份。
- 不支持后台系统服务、锁屏/UAC 安全桌面或远程桌面等未验证场景。

排查
1. 先确认鼠标连接正常，且发送端的目标、接收端的来源互相对应。
2. 检查双方是否点击“保存并应用”，端口是否一致；Windows 防火墙设置由你自行处理。
3. 系统声音发送源须与应用实际使用的播放设备一致；麦克风需要 Windows 允许桌面
   应用访问。设备被独占时尝试关闭占用它的应用。
4. 接收状态正常却会议软件没声音：核对 CABLE Input / CABLE Output 的方向，并查看
   会议软件自身的输入音量、静音和麦克风权限。
5. 设备不可用时选择正确设备并应用；查看窗口下方的状态说明。

验证边界
本版已通过本机自动化测试，包含合成声音样本的真实 TCP/TLS 传输与重连、错误配对码、
未授权来源、伪造接收端认证、取消阻塞读取、样本与帧长度校验、配置恢复及界面渲染。
测试没有采集用户的真实声音。尚未用两台实体电脑及虚拟音频设备完成端到端验收，
也没有测量真实延迟；请将它作为可试用的实验版。
