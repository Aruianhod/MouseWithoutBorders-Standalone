无界鼠标独立版 0.102.2933.13 · 一键配置声音与麦克风（实验版）

推荐：两台各一键配置一次
1. 两台完整解压新版，先完成鼠标配对。
2. 耳机/麦克风插在 A：A 右键托盘 →“一键配置耳机与麦克风…”，选择 B，然后选择
   “耳机和麦克风插在这台电脑（主电脑）”，点击“一键配置”。
3. B 打开同一入口，选择 A，然后选择“这台使用另一台的耳机和麦克风（副电脑）”，
   保持“设为本机默认麦克风”勾选，再选择播放位置，点击“一键配置”。
4. B 缺少虚拟设备时会校验、解压并启动随包附带的官方 VB-CABLE 安装程序。请确认
   Windows 管理员提示；若官方安装窗口仍需操作，请完成安装。程序不会代点系统授权。
5. 设备尚未就绪时会保存进度，并设置一次性的登录后启动。请自行重启 Windows，
   登录后程序会继续配置；不要移动程序目录。若未自动打开，手动启动本程序即可继续。
6. 完成后无需再选 CABLE Input/Output。使用“系统默认麦克风”的应用会使用远端麦克风；
   已经固定为某个独立设备的会议/游戏软件，仍需改为“系统默认”或 CABLE Output，
   某些应用需要重新打开。不能保证替所有第三方软件覆盖其专属设置。

新增：仅主电脑播放（.13）
在副电脑的一键配置中选择“播放位置：仅主电脑播放”，再点击“一键配置”。
主电脑配置不需要重做；升级保留旧模式，不会自动改变现有声音输出。
副电脑系统声音改送到独立的 Hi-Fi Cable，主电脑接收后通过耳机播放；
远端麦克风仍送到 VB-CABLE，两个通道分开，不混在一起。
副电脑缺少 Hi-Fi Cable 时，会从 VB-Audio 官网下载原版安装包并校验，
请在官方窗口点击 Install。首次需要联网，可能要重启；不需要运行 ASIO Bridge。
驱动和程序升级互相独立：仅在主动应用该模式时安装，不会随升级自动安装驱动。
已打开或固定指定扬声器的游戏/播放器，请改为“系统默认”并重开；程序不会覆盖应用专属路由。
主电脑离线或退出时，副电脑在此模式下不会自动从扬声器播放。
需要副电脑本地声音：选回“两边同时播放”，或“还原一键配置”；“停止全部音频共享”也恢复播放设备。
仅退出程序不会恢复默认播放设备，若需离线使用扬声器，请先切回两边播放或停止共享。
不卸载驱动，不修改扬声器静音开关，不要求关闭 Windows 安全保护。
Hi-Fi Cable / ASIO Bridge 来源及许可：https://vb-audio.com/Cable/ 、https://vb-audio.com/Services/licensing.htm
它们是 VB-Audio 捐赠软件；安装包按需直接从官方获取，不包含在本程序发布包中。
已校验官方下载文件及安装器签名；尚未在副电脑验证驱动和实际声音。

一键配置会做什么
- A：自动选择当前默认耳机/播放设备和麦克风，接收 B 的系统声音，发送麦克风给 B。
- B：按所选播放位置发送系统声音，接收 A 的麦克风到 VB-CABLE；勾选默认选项时，
  同时设置 Windows 普通、多媒体和通话的默认麦克风。
- 配置之前会备份原来的音频路由及默认播放/录音设备；若安装器将播放设备切到虚拟
  音频线，会尝试恢复原来的播放设备，避免本机突然无声及音频循环。
- “还原一键配置”恢复备份的音频路由，以及仍由本程序指定的默认设备；你后来手动
  选择的新默认设备会保留。它不会卸载 VB-CABLE。还原失败时保留备份供后续恢复。
- “停止全部音频共享”还会取消待完成的一键配置，避免下次启动又继续开启共享。
- 一键配置不能替另一台确认管理员提示，因此两台需各操作一次，不会远程安装驱动。
- 网络仍需允许本程序通信，音频端口两台应一致；默认 15102。不会自动修改防火墙。

随包驱动说明
附带的是官方原版 VB-CABLE 基础包，来源 https://vb-audio.com/Cable/。
VB-CABLE 是 VB-Audio 的捐赠软件，欢迎捐赠或购买许可；完整说明在 Drivers/VB-CABLE-NOTICE.txt。
官方安装程序已在打包时验证 Windows 数字签名，运行前再次核对固定 SHA-256。
驱动可能需要重启才能生效，Windows 提示仍由你确认。测试未实际安装驱动或改动本机默认设备。

以下是高级配置说明；使用上面的一键配置后通常不必手动接线。

支持什么
系统声音和麦克风各有“发送”和“接收”开关。可分别选择电脑、设备和 0–100% 音量。
设置会记住，程序下次启动后按配置恢复；网络或音频设备恢复后会自动重试。
默认四项全部关闭。只有启用发送、鼠标连接已认证、对方启用对应接收并通过音频认证后，
才会打开本机的相应采集设备。关闭共享会停止采集；程序不保存录音文件。

重要区别
系统声音共享：把所选播放设备正在播放的声音，送到另一台的耳机/音箱。
麦克风共享：把本机所选麦克风送到对端所选“播放设备”。若对端应用需要把它当麦克风，
对端须有虚拟音频设备（一键配置可以安装），把播放端的声音转到录音端。仅选择音箱/耳机属于监听，不会让
会议软件凭空出现一个新的麦克风设备。
例如 VB-CABLE：本程序接收麦克风时选择 CABLE Input（播放端）；会议/游戏软件的
麦克风选择 CABLE Output（录音端）。两者名称容易混淆，请按播放/录音端区分。
选择一键配置会按需调用随包官方安装程序；也可以自行安装其他虚拟设备，再手动选择。
官方说明及下载：https://vb-audio.com/Cable/

示例：耳机和麦克风插在 A，听 A/B 两台声音，B 也能使用 A 的麦克风
1. 两台退出旧版并解压完整新版，先完成鼠标配对。连接记忆与剪贴板功能保持可用。
2. 在 B 通过一键配置或自行安装虚拟音频设备，并按其要求重启。A 不需要虚拟音频设备。
3. 两台右键托盘图标，打开“声音与麦克风共享…”。设置页也有入口。
4. A 的“系统声音”页：
   - 发送：关闭。
   - 接收：开启，电脑选 B，设备选 A 的耳机，音量按需设置。
5. A 的“麦克风”页：
   - 发送：开启，电脑选 B，设备选 A 的物理麦克风，音量先用 100%。
   - 接收：关闭。
6. B 的“系统声音”页：
   - 发送：开启，电脑选 A，设备选 B 上应用实际正在播放声音的设备。
   - 接收：关闭。
7. B 的“麦克风”页：
   - 发送：关闭。
   - 接收：开启，电脑选 A，设备选 CABLE Input 或同类虚拟设备的播放端。
8. 两台端口均保留 15102，点击“保存并应用”。在 B 的会议/游戏软件中，将麦克风
   改为 CABLE Output。B 的应用扬声器仍用第 6 步选择的系统播放设备。
9. 检查窗口下方状态；两项对应通道应显示“正在发送”/“正在接收”。分别测试音乐、
   说话、静音和程序重启。不要仅凭“正在连接”判断声音已送达应用。

其他配置
- 可交换 A/B 角色。每种发送流一次选择一台电脑，每种接收流一次接受一个选定来源。
- 可以同时发送系统声音和麦克风，也可同时接收两种声音，使用独立设备和音量。
- 麦克风接收要求明确选择设备，避免无意播放到 Windows 默认音箱。
- “跟随 Windows 默认设备”会在默认设备改变后重建音频连接；指定的设备不可用时，
  会等待它恢复，不会悄悄改用其他麦克风。插拔设备后也可点击“刷新设备”重新选择。
- 两个方向同时发送系统声音时，接收输出必须与本机系统声音采集设备不同；同一个
  播放设备会被拒绝，以免声音循环放大。物理扬声器的声音仍可能被麦克风再次采集，
  建议使用耳机。本版不提供回声消除、降噪或远端虚拟设备驱动。
- “停止全部音频共享”立即停止当前音频，并保存四个开关为关闭。鼠标/剪贴板继续工作。
  正常关闭配置窗口不会停止已启用的共享。
- 发送系统声音不会自动静音源电脑，也不会更改 Windows 默认音频设备。

网络、延迟和配置
- 音频使用单独的 TCP 端口，默认 15102；两台必须设置相同端口，并允许可信局域网
  访问该端口。鼠标和剪贴板仍使用各自端口，不要将音频端口设为它们的端口。
- 声音连接使用 TLS 加密和双向配对码验证，复用已有的配对关系；配对码不会存入
  audio.json。鼠标连接断开或配对码改变时，音频通道会关闭并等待重新连接。
- 采用 48 kHz 浮点 PCM：系统声音立体声约 3.1 Mbit/s，麦克风单声道约 1.5 Mbit/s，
  不含网络/TLS 开销。没有采用有损压缩；面向可靠局域网。
- 接收缓冲上限默认 160 毫秒，可调 60–500 毫秒。它不是端到端延迟承诺；声卡、网络、
  队列和播放器都会增加延迟。拥塞时丢弃积压音频以追赶实时位置，可能出现短暂断音。
- 配置：%LOCALAPPDATA%\MouseWithoutBordersStandalone\audio.json；前一份为 audio.json.bak。
  损坏配置会停用音频并显示错误，不会覆盖原文件。可退出后保留原文件并恢复备份。
- 不支持后台系统服务、锁屏/UAC 安全桌面或远程桌面等未验证场景。

排查
1. 先确认鼠标连接正常，且发送端的目标、接收端的来源互相对应。
2. 检查双方是否点击“保存并应用”，端口是否一致；Windows 防火墙设置由你自行处理。
3. 系统声音发送源须与应用实际使用的播放设备一致；麦克风需要 Windows 允许桌面
   应用访问。设备被独占时尝试关闭占用它的应用。
4. 接收状态正常却会议软件没声音：核对 CABLE Input / CABLE Output 的方向，并查看
   会议软件自身的输入音量、静音和麦克风权限。
5. 设备不可用时选择正确设备并应用；查看窗口下方的状态说明。

验证边界
本版已通过本机自动化测试，包含合成声音样本的真实 TCP/TLS 传输与重连、错误配对码、
未授权来源、伪造接收端认证、取消阻塞读取、样本与帧长度校验、配置恢复及界面渲染。
测试没有采集用户的真实声音。尚未用两台实体电脑及虚拟音频设备完成端到端验收，
也没有测量真实延迟；请将它作为可试用的实验版。
